# テスト仕様書

## 1. 概要

本ドキュメントは `tdb`（Tiny Debugger）のテスト仕様を示すものです。
主に `testprog.c` / `testprog2.c` / `testprog3.c` / `testprog4.c` を対象プログラムとして、各機能が正しく動作するかを確認します。

なお、本章のテストケース（T01〜M12・Q02・Q03 等）の多くは、`tests/run_tests.ps1`（PowerShell 7 / `pwsh` 実行）として自動実行できます（v3.0 で追加）。Ctrl+C 割り込みが必要なもの（C01）や特定の実行時条件を要するもの（C02/C03）など、自動化できないものは意図的にスキップとして扱われます。詳細は 4 章参照。

## 2. テスト環境

| 項目 | 内容 |
|------|------|
| OS | Windows |
| ビルド | `make.bat`（`win_bison`/`win_flex` でコマンド行・式評価器の文法からパーサを生成した後 `cl` でビルドする、v1.9） |
| 対象プログラム | `testprog.exe`, `testprog2.exe`, `testprog3.exe`（マルチスレッド機能確認用、v2.0）, `testprog4.exe`（マルチプロセス機能確認用、v3.0） |
| デバッガ | `tdb.exe` |
| 前提条件 | PDB シンボルが生成されていること（`/Zi` / `/Zi`）。`win_bison`/`win_flex`（winflexbison パッケージ）が `PATH` 上にあること（v1.9） |
| 自動テスト実行環境（v3.0） | PowerShell 7（`pwsh`）。文字コード（UTF-8, BOM なし）の解釈違いにより、Windows 標準の `powershell.exe`（5.1 系）では文字化けやパースエラーが発生するため、必ず `pwsh` を使用すること |

## 3. テスト対象

- プロセス起動・再開・再起動・強制終了
- ブレークポイント設定・ヒット・解除
- ステップ実行（si / step / next / up）
- レジスタ・メモリ・ソース表示
- 逆アセンブル・バックトレース
- 式評価と値表示
- 変数代入
- メモリリーク追跡
- 停止時の PID/TID 表示
- ウォッチポイント設定・ヒット・解除
- コマンドヘルプ
- マルチスレッド管理（スレッド生成/終了通知、スレッド一覧、フォーカス切替・自動固定、全スレッド対応ウォッチポイント）（v2.0）
- マルチプロセス管理（子プロセス生成/終了通知、プロセス一覧、プロセス切替）（v3.0）

## 4. テスト準備

```bat
make.bat
```

実行例：

```bat
tdb.exe testprog2.exe
```

### 4.1 自動テスト実行（v3.0）

上記ビルド後、以下でテスト仕様書の主要なテストケースを自動実行できます。

```powershell
cd tests
pwsh -File run_tests.ps1
```

| オプション | 内容 |
|---|---|
| `-VerboseOutput` | 各テストの `tdb.exe` 実際の出力全文を表示する（失敗時の原因調査用） |
| `-Only '<正規表現>'` | ID が一致するテストのみ実行する（例: `-Only 'M0[1-9]'`） |

コンパイル警告有無の確認（Q01）はフルリビルドを伴うため上記スイートには含めておらず、別途 `pwsh -File tests\check_build_warnings.ps1`（Developer Command Prompt 環境が必要）で確認する。

## 5. テストケース

### 5.1 起動・基本操作

| ID | 操作 | 入力 | 期待結果 |
|----|------|------|----------|
| T01 | デバッガ起動 | `tdb testprog2.exe` | 対象プログラムが起動し、エントリーポイントで停止。process id/thread id が表示される。 |
| T02 | ヘルプ表示 | `help` または `h` | 利用可能なコマンド一覧が表示される。 |
| T02a | コマンド別詳細ヘルプ | `help break` | `break` コマンドの用法・引数の意味・使用例を含む詳細説明が表示される。 |
| T02b | エイリアス指定での詳細ヘルプ | `help p` または `h s` | `p`（print のエイリアス）・`s`（step のエイリアス）それぞれの詳細説明が表示される（対応する正式名のものと同じ内容）。 |
| T02c | 未知のトピック | `help nosuchcmd` | `no help available for 'nosuchcmd'` に続けて有効なトピック名一覧が表示される。 |
| T03 | 実行継続 | `continue` または `c` | プログラムが最後まで実行されるか、次のブレークポイントで停止する。 |
| T04 | 終了 | `quit` | デバッガが終了する。 |
| T05 | 強制終了 | `kill` | 対象プロセスが強制終了し、「killed process」と表示された後、debugger_loop が EXIT_PROCESS を検出してデバッガが終了する。 |

### 5.2 ブレークポイント

| ID | 操作 | 入力 | 期待結果 |
|----|------|------|----------|
| B01 | 関数シンボルで BP 設定 | `break main` | `breakpoints set at ...` のようなメッセージ。 |
| B02 | ファイル:行番号で BP 設定 | `break testprog2.c:49` | 指定行にブレークポイントが設定される。 |
| B03 | アドレスで BP 設定 | `break 0x140001000` | 指定アドレスにブレークポイントが設定される。 |
| B04 | BP 一覧 | `show bp` | 設定済みブレークポイントのアドレス一覧が表示される。 |
| B05 | BP 削除 | `del main` | main 関数のブレークポイントが削除される。 |
| B06 | 番号指定での BP 削除（v1.10） | `show bp` で番号確認後 `del 1` または `del #1` | `show bp` の `#1` に表示されたブレークポイントが削除される（`breakpoint removed at ...` と表示）。 |
| B07 | 存在しない番号の削除（v1.10） | `del 99` | `no breakpoint with index #99` と表示される。 |
| B08 | 再帰関数への BP、複数回ヒット（v1.10 回帰テスト） | `break factorial` で BP 設定後 `continue` を 5 回繰り返す（`testprog2.exe` の `factorial(5)`） | 5 回とも `hit breakpoint at ...` で正しく停止し、`p n` の値が `5, 4, 3, 2, 1` と順に表示される（2 回目以降が `breakpoint ... (not tracked)` にならないこと）。 |
| B06 | BP ヒット | `c` | ブレークポイントで停止し、停止位置が表示される。 |

### 5.11 マルチスレッド管理（v2.0、`testprog3.exe` 使用）

`testprog3.exe` は共有変数 `g_shared` を `InterlockedIncrement` で更新するワーカースレッドを 3 本生成する。

| ID | 操作 | 入力 | 期待結果 |
|----|------|------|----------|
| M01 | スレッド生成通知 | `break worker` で BP 設定後 `continue` | 3 本のワーカースレッド生成時にそれぞれ `thread created id=<TID>` が表示される。 |
| M02 | 複数スレッドでの BP ヒット | `continue` を 3 回繰り返す | 3 回とも `hit breakpoint at ...` で停止し、そのたびに異なる `thread id=<TID>` が表示される。`regs` の値（RCX/R8 等、`worker` の引数）も呼び出しごとに異なる正しい値を示す（1 本目のスレッドの値が使い回されないこと）。 |
| M03 | スレッド一覧表示 | `show threads` | 生存中の全スレッド ID が一覧表示され、フォーカス中のスレッドに `(current)` が付記される。 |
| M04 | フォーカス自動固定 | M02 の 1 回目のヒット直後に `show threads` | 最初に停止したスレッドに `(current, locked)` が付記される（`thread lock` を明示的に打たなくても固定される）。 |
| M05 | フォーカス外スレッドの自動継続 | フォーカス固定中に `continue` | フォーカス外のスレッドが同じ BP にヒットしても対話プロンプトは止まらず、`thread id=<TID> hit breakpoint at <addr> (not focused, continuing)` の 1 行のみが表示され自動的に実行が継続される。 |
| M06 | フォーカス切替 | `thread <他のTID>` | 指定したスレッドへフォーカスが切り替わり、`switched to thread id=<TID> RIP=0x...` が表示される。以後の `regs` はそのスレッドの値を示す（フォーカス切替時点で停止していない、実行中のスレッドの現在値も取得できる）。 |
| M07 | フォーカス固定の明示解除 | `thread unlock` | `focus pin released ...` と表示される。以後、次に実際に停止したスレッドで自動的に再固定される。 |
| M08 | フォーカス固定の明示設定 | `thread lock` | `focus (re-)pinned to thread id=<TID> ...` と表示される。 |
| M09 | スレッド終了通知 | ワーカースレッドが終了するまで `continue` | 各スレッドの終了時に `thread exited id=<TID> exit code=0` が表示され、`show threads` の一覧から消える。 |
| M10 | フォーカス中スレッドの終了 | フォーカス固定中のスレッドが終了する場合 | フォーカス固定が自動的に解除され、以後は他のスレッドの停止で再固定される（無応答にならない）。 |
| M11 | 全スレッド対応ウォッチポイント | BP を設定せず `watch g_shared` のみ設定して `continue` を複数回繰り返す | `g_shared` への書き込みがどのワーカースレッドで発生しても `watchpoint 0 hit: write at ...` が検知され、`thread id` がヒットごとに異なりうる。 |
| M12 | 存在しない TID 指定 | `thread 99999999` | `no such thread id=99999999` と表示される。 |

### 5.12 マルチプロセス管理（v3.0、`testprog4.exe` 使用）

`testprog4.exe` は引数なしで起動すると自分自身を子プロセスとして起動し（`CreateProcess` に `"child"` 引数を渡す）、子プロセス側で `worker(n)` を 3 回呼び出してから終了する。親プロセスは子プロセスの終了を待ち合わせる。

| ID | 操作 | 入力 | 期待結果 |
|----|------|------|----------|
| MP01 | 子プロセス生成通知 | `continue` | 子プロセスの生成時に `process created id=<PID>` が表示される。対話プロンプトは止まらない。 |
| MP02 | プロセス一覧表示 | `break worker` で BP 設定後 `continue`、続けて `show processes` | 親・子両方の PID が一覧表示され、フォーカス中のプロセスに現在選択中である旨（`(current)`）が付記される。 |
| MP03 | ブレークポイントのプロセス間非伝播 | 親プロセスで `break worker` を設定したまま `continue` | 親プロセスで設定したブレークポイントは子プロセスには伝播しないため、子プロセスの `worker` 呼び出しでは止まらない（子プロセス自身の初回停止＝起動直後の未トラッキングブレークポイントでのみ停止する）。 |
| MP04 | プロセス切替 | `process <子PID>`（`show processes` で確認した PID） | 指定したプロセスへフォーカスが切り替わり、`switched to process id=<PID>, thread id=<TID> RIP=0x...` が表示される。 |
| MP05 | 切替後のブレークポイント設定・ヒット | プロセス切替後に `break worker`、`continue` | 子プロセス自身の `worker` にブレークポイントが設定され、子プロセスの PID/TID で停止する。ソース行表示・`p n` 等の変数参照も子プロセスのメモリを対象に正しく機能する。 |
| MP06 | 存在しない PID 指定 | `process 99999999` | `no such process id=99999999` と表示される。 |
| MP07 | プロセス終了通知 | ブレークポイントを設定せず `continue` を繰り返し、子プロセスが終了するまで進める | 子プロセスの終了時に `process exited id=<PID> exit code=0` が表示され、`show processes` の一覧から消える。その後、親プロセス自身の終了（`quit` を待つ状態）まで正しく進む。 |

## 6. 非機能・品質確認

| ID | 項目 | 確認方法 |
|----|------|----------|
| Q01 | コンパイル警告なし | `make.bat` 実行時に警告が出ないこと。自動実行する場合は `pwsh -File tests\check_build_warnings.ps1`（v3.0、Developer Command Prompt 環境が必要）。 |

## 7. 備考

- `p` は `print` のエイリアス、`c` は `continue` のエイリアス、`s` は `step` のエイリアス。
- 式評価は C 言語のサブセットを対象とする。副作用のある式（`i++` など）は未対応の場合がある。
- シンボル情報がない場合、ソース行表示や変数名解決が制限される。
- v1.9 でコマンド行解析・式評価器の字句解析／構文解析部分を bison/flex ベースへ書き換えた。これに伴い、キャストの結合順位が C 言語本来の意味論（単項式レベル）に修正されており、`(int)a + b` の評価結果が旧版（`(int)(a + b)` 相当）と異なる点に留意する（E11 参照）。
- v1.9 で `help` コマンドにコマンド名（エイリアス可）の引数を追加した（T02a〜T02c 参照）。
- v1.10 で、再帰関数のブレークポイントが 2 回目以降のヒットで停止しない不具合を修正した（B08 参照）。あわせて `del` コマンドに `show bp` の表示番号（`#N`/`N`）指定での削除機能を追加した（B06・B07 参照）。
- v2.0 でマルチスレッド対応を追加した（M01〜M12 参照）。フォーカスは既定で「最初に実際に停止したスレッド」へ自動固定されるため、M04 のようにスレッド生成直後に `break`+`continue` した場合の 1 回目のヒットが基準になる。`show threads` を生成直後すぐに実行すると、OS 側の通知タイミング次第で全スレッドがまだ現れないことがある点に留意する（要件定義書 8 章参照、既知の制約でありテスト失敗ではない）。
- v2.0 時点で、`up` コマンドはローカル変数を持つ関数に対して正しいリターンアドレスを取得できない既知の不具合がある（要件定義書 8 章参照）。S04（アンティルリターン）のテストは、この制約の影響を受けない対象（ローカル変数がほぼ無い関数）を選ぶか、既知の不具合として結果を解釈すること。
- v3.0 でマルチプロセス対応を追加した（MP01〜MP07 参照）。ブレークポイント・ウォッチポイントはプロセスごとに独立しており、親プロセスで設定したものは子プロセスへ自動伝播しない（MP03、意図的な仕様であり不具合ではない。要件定義書 4.2 節参照）。フォーカス固定はスレッド ID の一意性を利用してプロセスをまたいでも成立するため、M04〜M08 の仕組みは `process <id>` 切替後もそのまま適用される。
- v3.0 で、テスト仕様書のテストケース（T01〜M12 等）の多くを自動実行する PowerShell スクリプト `tests/run_tests.ps1` を追加した。個別のテストで判明した既知の非決定性（M01 のスレッド生成通知件数、上記 v2.0 の注記と同根）は、自動テスト側では「1 件以上」のように緩めた条件で検証している。
