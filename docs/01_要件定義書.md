## 1. システム概要

windbg は、Windows (x64) 上で動作するコンソールアプリケーション（EXE）を対象とした、コマンドライン対話型のネイティブデバッガである。Win32 デバッグ API（`CreateProcess` / `WaitForDebugEvent` / `ContinueDebugEvent` 等）と DbgHelp ライブラリ（PDB シンボル解析）を用いて実装されており、GDB に類似したコマンド体系（`break`, `continue`, `si`, `print` 等）を提供する。

対象プログラムを子プロセスとして起動し、ソフトウェアブレークポイント（INT3 命令）、ハードウェアウォッチポイント（DR0〜DR3 デバッグレジスタ）、シングルステップ実行、全汎用レジスタ表示（RIP/RAX〜R15/RFL）／浮動小数点レジスタ（ST0-ST7/XMM0-XMM15）表示／メモリ参照、簡易 C 言語式評価、逆アセンブル、バックトレース表示、停止時の PID/TID 表示などの機能により、実行中プログラムの状態を調査・変更できる。対象プログラムがマルチスレッドの場合は、生存中の全スレッドを追跡・一覧表示し、フォーカス（対話コマンドの対象スレッド）の切替・自動固定にも対応する（v2.0）。対象プログラムがさらに子プロセスを生成する場合は、その子プロセス（および孫プロセス以降）も自動的に追従デバッグし、`process <id>`/`show processes` によるプロセス切替・一覧表示に対応する（v3.0）。

## 2. 目的・背景

- Visual Studio でビルドされた C/C++ 実行ファイル（PDB 付き）を、外部ツールに頼らずソースレベルでデバッグ・解析できる軽量なコマンドラインデバッガを提供すること。
- Win32 デバッグ API・DbgHelp API・x64 命令デコードの学習・実験用途を兼ねること（`testprog.c`／`testprog2.c` は動作確認用のサンプル対象プログラムとして同梱されている。前者は構造体・配列・ポインタ・`malloc`/`free`、後者は共用体・グローバル変数・再帰関数・ループを中心にカバーする）。

## 3. 用語定義

| 用語 | 説明 |
|---|---|
| デバッギ（debuggee） | windbg がデバッグ対象として起動した子プロセス |
| ブレークポイント | 対象アドレスの先頭バイトを `0xCC`（INT3）に書き換えることで実現する実行停止点 |
| 一時ブレークポイント（temp bp） | `up` / `n`（next）コマンド実装のために、関数リターン先などへ一時的に設定されるブレークポイント |
| シンボル | PDB に含まれる関数名・変数名・型情報・行番号対応（DbgHelp/SymXxx API 経由で取得） |
| lvalue | 式評価器において、デバッギのメモリ上に実体を持ち読み書き可能な式（変数・メンバ・配列要素など） |
| プロローグスキップ | 関数先頭アドレスにブレークポイントを置く際、スタックフレーム構築命令群を飛ばして最初の実行可能なソース行へ補正する処理 |
| フォーカス（focus） | 対話コマンド（`regs`/`si`/`step`/`n`/`dis`/`tb`/`x`/`set <reg>` 等）が対象とする「現在のスレッド」（`dbg->tid`/`dbg->thread`）（v2.0） |
| フォーカス固定（pin） | 特定スレッドをフォーカスに固定し、他スレッドの同種の停止要因（トラッキング済みブレークポイント／ウォッチポイント／ステップ着地）を対話プロンプトへ入らず自動継続させる機能（`thread lock`/`thread unlock`、既定で自動有効。v2.0） |
| プロセス管理（process registry） | windbg 自身が起動したルートプロセスと、その子孫として生成された全プロセスを追跡する仕組み（`processes.c`、`process_entry_t` 連結リスト）。`debugger_t` の各種状態（ブレークポイント・シンボル・ウォッチポイント・スレッド一覧等）は「現在アクティブなプロセス」のものを常に指し、非アクティブな各プロセスの状態は `process_entry_t` に退避される（v3.0） |

## 4. 適用範囲

### 4.1 対象とする範囲
- Windows x64 上で、windbg 自身が `CreateProcess` により起動したネイティブ（C/C++ 由来）コンソールプログラムのデバッグ
- 対象プログラム（またはその子孫プロセス）がさらに子プロセスを生成した場合の自動追従デバッグ、プロセス一覧表示（`show processes`）・プロセス切替（`process <id>`）（v3.0）
- 対象プログラムがマルチスレッドの場合の、生存中の全スレッドの追跡・一覧表示（`show threads`）・フォーカス切替（`thread <id>`）・フォーカス固定（`thread lock`/`thread unlock`、既定で自動有効）（v2.0）。プロセスをまたいだフォーカス固定も、Windows のスレッド ID がプロセス間で重複しないことを利用して同じ仕組みで実現する（v3.0）
- PDB シンボル情報が取得できる場合のソースレベル表示（ソース行、変数、バックトレース）
- x64 命令の主要なサブセットに対する逆アセンブル表示
- `malloc`/`free` の呼び出しを追跡するメモリリーク検出（対象がこれらのシンボルを解決できる場合に限る。4.2 節・5 章参照）
- ブレークポイント・シングルステップ等で停止した際のデバッギの PID/TID 表示

### 4.2 対象外とする範囲
- 既に起動済みの、windbg 自身が生成していない任意のプロセスへのアタッチ（あくまで windbg 自身が `CreateProcess` で生成したプロセスとその子孫のみを対象とする。v2.0 までは `DEBUG_ONLY_THIS_PROCESS` でルートプロセスのみを対象としていたが、v3.0 で子プロセス追従のため `DEBUG_PROCESS` へ変更した）
- ブレークポイント・ウォッチポイントのプロセス間自動伝播（各プロセスのブレークポイント／ウォッチポイントは独立しており、あるプロセスで設定したものが自動的に別プロセス（子・親とも）へ引き継がれることはない。子プロセス側でも必要な箇所に改めて `break`/`watch` を設定する運用とする。v3.0 で意図的にこの挙動を採用した設計判断であり、不具合ではない）
- GUI・リモートデバッグ・カーネルデバッグ
- 条件付きブレークポイント、ウォッチポイント（メモリ書込監視）
- x86（32bit）ターゲットのフルサポート（レジスタ表示のみ `_WIN64` 分岐で対応、逆アセンブラ・式評価は 64bit 前提）
- `realloc`/`calloc`/`new`/`delete` のリーク検出（`malloc`/`free` のみが対象）
- CRT が動的リンク（既定の `/MD`）された対象のリーク検出（`malloc`/`free` が対象 EXE 自身のモジュールに無いためシンボル解決できない。5 章参照）

## 5. 前提条件・制約条件

- 実行環境は Windows（Win32 API, `dbghelp.lib` に依存）であること。
- windbg 自体は x64/x86 いずれの構成でもビルド可能（`windbg.slnx` に Platform 定義あり）だが、内部処理（レジスタ名、式評価のポインタサイズ＝8バイト固定など）は x64 実行を前提とした作りになっている。
- ソース行表示・変数参照・シンボル検索・バックトレースは対象 EXE に対応する PDB が存在し、かつソースファイルが `list.FileName` が指すパスで実際に読み出せることを前提とする（PDB が無い/ソースが見つからない場合は当該機能のみ利用不可）。
- 起動時の引数は `windbg.exe <target.exe>` の 1 つのみで、対象は常に 1 プロセスのみを扱う。対象プロセスがマルチスレッドの場合は `CREATE_THREAD_DEBUG_EVENT`/`EXIT_THREAD_DEBUG_EVENT` を検知してスレッド一覧（`thread_entry_t` 連結リスト、threads.c）を管理し、`dbg->tid`/`dbg->thread` は「フォーカス中のスレッド」を指す（v2.0）。
- `leak on` によるメモリリーク検出は、対象 EXE が CRT を静的リンク（`/MT` または `/MTd`）しており `malloc`/`free` のシンボルが対象 EXE 自身のモジュールから解決できることを前提とする。エントリフック（`malloc`/`calloc`/`realloc`/`free` の呼び出し検知）は他スレッドの一時停止（`suspend_other_threads`）で保護されるが、確保関数のリターンアドレス追跡用の一時ブレークポイントは 1 スロットのみのため、複数スレッドが同時に確保関数の内部を実行中の場合はこの部分の追跡が競合しうる（8 章参照）。

## 6. 機能要件

対話コマンドは `command_loop`（commands.c）が 1 行読み取った後、bison/flex で生成したコマンドライン文法（`cmdline_parser.y`/`cmdline_lexer.l`、v1.9）でキーワード・引数を認識し、対応する `do_xxx()` ハンドラ（commands.c）へディスパッチする（詳細は詳細処理設計書 6 章参照）。

### 6.1 プロセス制御

| コマンド | 書式 | 内容 |
|---|---|---|
| （起動） | `windbg.exe <target.exe>` | 対象プログラムをデバッグ対象として起動する |
| `run` | `run` | 現在のブレークポイント等を破棄し、対象プログラムを最初から再起動する |
| `quit` | `quit` | windbg を終了する（対象プロセスは終了処理されず残る場合がある） |
| `kill` | `kill` | デバッグ中の対象プロセスを強制終了する。終了後は debugger_loop が EXIT_PROCESS を検出して windbg も終了する |

### 6.1.1 マルチスレッド管理（v2.0）

対象プログラムがマルチスレッドの場合、windbg は `CREATE_THREAD_DEBUG_EVENT`/`EXIT_THREAD_DEBUG_EVENT` を検知して生成・終了を通知し、生存中のスレッド一覧（`thread_entry_t` 連結リスト、threads.c）を管理する。スレッドの生成・終了自体は対話プロンプトを止めず自動的に実行を継続する。

| コマンド | 書式 | 内容 |
|---|---|---|
| （通知） | （自動） | スレッド生成時に `thread created id=<TID>`、終了時に `thread exited id=<TID> exit code=<code>` を表示する |
| `show threads` | `show threads` | 生存中のスレッド ID を一覧表示する。フォーカス中のスレッドには `(current)`、フォーカス固定中は `(current, locked)` を付記する |
| `thread <id>` | `thread <id>` | 指定 TID へフォーカスを切り替える。以後 `regs`/`si`/`step`/`n`/`dis`/`tb`/`x`/`set <reg>` は当該スレッドを対象とする。同時にフォーカス固定も当該スレッドへ更新される |
| `thread lock` | `thread lock` | 現在のスレッドへ明示的にフォーカスを固定する |
| `thread unlock` | `thread unlock` | フォーカス固定を解除する（次に実際に停止したスレッドで自動的に再固定される） |

**フォーカス自動固定（既定で有効）**: トラッキング済みブレークポイント・ウォッチポイント・ステップ着地により最初に実際に停止したスレッドが自動的にフォーカスとして固定される。以後、別のスレッドが同種の停止要因に遭遇しても対話プロンプトへは入らず、「`thread id=<TID> hit breakpoint at <addr> (not focused, continuing)`」のような 1 行のメッセージのみを表示して自動的に実行を継続する。未トラッキングのブレークポイント（起動直後の ntdll 初期停止等）や Ctrl+C 割り込みはフォーカス固定のトリガーにはならない（常に表示・停止する）。フォーカス中のスレッドが終了した場合は固定が自動解除され、次に停止したスレッドへ引き継がれる。

### 6.1.2 プロセス管理（v3.0）

windbg は起動時に指定した対象プログラム（ルートプロセス）に加え、そのプロセス（または、そこからさらに生成された子孫プロセス）が `CreateProcess` 等で新たに生成した子プロセスも自動的に追従デバッグする。`CREATE_PROCESS_DEBUG_EVENT` を検知するたびに、そのプロセスの実行ファイルパスを取得してプロセス一覧へ登録し、専用のシンボルハンドルを初期化する。新規プロセスの出現自体は対話プロンプトを止めず自動的に実行を継続する。

| コマンド | 書式 | 内容 |
|---|---|---|
| （通知） | （自動） | 子プロセス生成時に `process created id=<PID>`、終了時に `process exited id=<PID> exit code=<code>` を表示する |
| `show processes` | `show processes` | 追跡中の全プロセス（ルートプロセスと子孫プロセス）を一覧表示する。フォーカス中のプロセスには現在選択中である旨を付記する |
| `process <id>` | `process <id>` | 指定 PID へフォーカスを切り替える。以後のブレークポイント・ウォッチポイント・変数参照・`thread`/`show threads` 等はすべて当該プロセスのものを対象とする。同時にフォーカスは当該プロセスの最初に判明しているスレッドへ移り、そのスレッドへフォーカス固定される |

各プロセスのブレークポイント・ウォッチポイント・シンボル情報・スレッド一覧・リーク追跡状態は完全に独立している。あるプロセスで `break`/`watch` を設定しても、別のプロセス（親・子いずれも）には自動的には反映されない（4.2 節参照）。フォーカス固定（pin）は Windows のスレッド ID がプロセスをまたいで重複しないことを利用して、スレッド単位の仕組みをそのまま流用する。すなわち、あるプロセスの特定スレッドにフォーカスが固定されている間、別プロセスの別スレッドが同種の停止要因に遭遇した場合も、6.1.1 節の「フォーカス外スレッドの自動継続」と同じ扱いになる。

### 6.2 ブレークポイント管理

| コマンド | 書式 | 内容 |
|---|---|---|
| `break` / `b` | `break <addr\|symbol\|file:line>` | 指定位置にソフトウェアブレークポイントを設定する。`0x` 始まりはアドレス直値、`:` を含む場合は `file:line`、それ以外はシンボル名として解決する。シンボル名指定時は関数プロローグを自動的にスキップする。同一箇所が再帰呼び出しやループで複数回実行された場合、そのたびに停止する。複数スレッドから同一アドレスに到達した場合も、それぞれ実際にヒットしたスレッドとして正しく停止する（v2.0） |
| `del` | `del <addr\|symbol\|file:line>` / `del <#N\|N>` | 指定位置のブレークポイントを削除する。引数の解釈は `break` と同様。引数が数字のみ（先頭の `#` は省略可）の場合は `show bp` に表示される番号を指定した削除として扱われる（v1.10） |
| `show bp` | `show bp` | 設定済みブレークポイントを一覧表示する。各行にインデックス・アドレスに加え、関数名＋オフセット、ソースファイル名＋行番号（解決できる場合）を表示する |

### 6.2.1 ウォッチポイント管理

ハードウェアデバッグレジスタ（DR0〜DR3 / DR7）を使ったウォッチポイント機能。最大 4 か所まで同時設定可能。指定アドレスへの書き込み（または読み書き）が発生した時点でプログラムを停止し、ヒット位置（RIP）とソース行を表示して `command_loop` に入る。ウォッチポイントヒットは `STATUS_SINGLE_STEP`（0x80000004）例外の DR6 ステータスビットで判定する。DR0〜DR3/DR7 はスレッドごとの CPU レジスタであるため、ウォッチポイントは生存中の全スレッドへ適用され（新規スレッド作成時にも自動的に反映）、どのスレッドが監視対象へ書き込み／読み取りを行っても検知する（v2.0）。

| コマンド | 書式 | 内容 |
|---|---|---|
| `watch` | `watch [/r] [/1\|/2\|/4\|/8] <addr\|symbol>` | ハードウェアウォッチポイントを設定する。`/r` で読み書き監視（既定は書き込みのみ）。`/1`〜`/8` でサイズ指定（既定 4 バイト）。最大 4 個まで |
| `wdel` | `wdel <addr\|symbol>` | 指定アドレスのウォッチポイントを削除する |
| `show wp` | `show wp` | 設定済みウォッチポイントを一覧表示する |

### 6.3 実行制御

| コマンド | 書式 | 内容 |
|---|---|---|
| `continue` / `c` | `continue` | 停止中の実行を再開する |
| `si` | `si` | 1 命令だけシングルステップ実行し、逆アセンブル 1 行を表示する |
| `step` / `s` | `step` | ソース行単位でステップイン実行する（行情報が無い場合は `si` にフォールバック） |
| `n`（next） | `n` | ソース行単位でステップオーバー実行する（行情報が無い場合は `si` にフォールバック） |
| `up` | `up` | スタック上のリターンアドレスを取得し、そこに一時ブレークポイントを設定して実行を再開する（呼び出し元へ抜けるまで実行） |
| **Ctrl+C 割り込み** | `Ctrl+C` | デバッガが対象プロセスに割り込みを送り、実行を中断する。`DBG_CONTROL_C` 例外を検出して停止位置を表示する |
| **アクセス違反処理** | （自動） | システム CRT 内で発生するアクセス違反（`EXCEPTION_ACCESS_VIOLATION`）は自動的に無視して実行を継続する。例外情報は表示される |

### 6.4 レジスタ操作

| コマンド | 書式 | 内容 |
|---|---|---|
| `regs` | `regs` | x64 では全汎用レジスタ（RIP/RAX〜R15/RFL）を 2 列表示し、浮動小数点レジスタ（ST0-ST7、XMM0-XMM15）をセクション分けして表示する。32bit ビルドでは EIP/EAX/EBX/ECX/EDX/ESP を 2 列表示する |
| `set <reg>=<expr>` | `set rax = 1+2` | レジスタへ式評価結果を書き込む。対象は RIP/RAX〜R15/EFLAGS に加え、x64 では XMM0〜XMM15（整数値または浮動小数点リテラルの下位 64bit）、ST0〜ST7（浮動小数点リテラル）。レジスタ名と解決できなければ変数として扱う |

### 6.5 メモリ参照

| コマンド | 書式 | 内容 |
|---|---|---|
| `x` | `x <0xADDR>` / `x rsp+N` / `x rsp-N` / `x rbp±N` | 指定アドレス（直値、または `RSP`/`RBP` 相対オフセット）から 16 バイトを 16 進ダンプ表示する |

### 6.6 逆アセンブル

| コマンド | 書式 | 内容 |
|---|---|---|
| `dis` | `dis` / `dis 0xADDR` / `dis <symbol>` / `dis <file:line>` / `dis <line>` | 指定位置（省略時は現在の RIP）から 10 命令分を逆アセンブル表示する |

### 6.7 ソースコード表示・シンボル情報

| コマンド | 書式 | 内容 |
|---|---|---|
| `list` / `l` | `list` / `list <line>` / `list <file:line>` | ソースファイルを行範囲表示する。引数省略時は現在停止位置周辺、以後 `list` を続けて呼ぶと続きの範囲を表示する（継続状態を保持）。ソースファイルが開けない場合は `(cannot open ...)` メッセージ後に逆アセンブル 1 行を表示する |

### 6.9 メモリリーク検出

| コマンド | 書式 | 内容 |
|---|---|---|
| `leak on` | `leak on` | `malloc`/`calloc`/`realloc`/`free` 呼び出しの追跡（インストルメンテーション）を開始する。対象の `malloc`/`free` シンボルが解決できない場合は失敗する（5章の制約参照）。`calloc`/`realloc` はオプション |
| `leak off` | `leak off` | 追跡を停止し、内部で保持している未解放確保の記録を破棄する |
| `show leaks` | `show leaks` | 現在追跡中の未解放確保（リーク）を一覧表示する（アドレス・サイズ・確保関数名・確保元の関数名＋ソース行）。プロセス終了時にも自動的に同じ内容が表示される |

`leak on` 実行中は、対象プログラムが `malloc`/`calloc`/`realloc`/`free` を呼び出しても対話プロンプトは止まらず、裏でサイズ・返却ポインタ・呼び出し元アドレス・確保関数名のみを記録して自動的に実行を継続する。エントリフックのヒットは、どのスレッドが呼び出したかに関わらず検知され、その計装処理中は他スレッドを一時停止して保護する（v2.0、5 章の制約も参照）。

## 8. 既知の制限・課題（要件レベル）

コード精査の結果、以下の制限・課題が存在する。設計・改修時の参考情報として記載する。

- ~~**コマンドディスパッチの前方一致依存**: `command_loop` は `strncmp` による前方一致の if-else チェーンで構成されており、コマンド文字列や判定順序次第では意図しない分岐に入りうる。~~ **v1.9 で解消**: コマンド行解析を bison/flex ベースの文法（`cmdline_parser.y`/`cmdline_lexer.l`）へ書き換え、各コマンドは行頭アンカー付きの単語境界一致で判定されるようになり、判定順序への依存はなくなった（詳細処理設計書 6 章参照）。
- **逆アセンブラは x64 命令の限定サブセットのみ対応**: SSE/AVX 命令、3 バイト opcode、多くの ModRM 拡張命令は `.byte 0xNN` や `op_NN` のプレースホルダ表示となる。
- **開発時デバッグ出力の残置**: `symbols.c` の未使用（死んだ）コード `print_struct` に `fprintf(stderr, "[debug] ...")` が残っている（`syms` コマンド用の `[SYMS] ...` ログは v1.8 で削除済み）。
- **固定サイズバッファ**: コマンド行 256 バイト、パス関連 512 バイト等、固定長バッファを用いた文字列処理が多く、長い入力・パスに対する明示的なエラーメッセージは無い場合がある。
- **スレッド生成通知の到達タイミング（v2.0 で判明）**: `CREATE_THREAD_DEBUG_EVENT` は `CreateThread()` がその呼び出し元へ制御を返すことと厳密には同期しておらず、OS 側の内部処理タイミング次第で通知の到達が遅れることがある。そのため、複数スレッドをタイトなループで連続生成した直後（例: ループを抜けた直後の行にブレークポイントを置いた場合）に `show threads` を実行すると、実際にはすでに `CreateThread()` が呼び出し元へ返っているスレッドが一覧にまだ現れないことがある（WinDbg 等でも起こりうる Win32 デバッグ API 由来の既知の挙動であり、windbg 側の登録漏れではない）。次に何らかのデバッグイベントが処理されたタイミングで反映される。
- **`up` のリターンアドレス取得の制約（既知の不具合、マルチスレッド対応スコープ外）**: `do_up`（`up` コマンド）は、停止位置の `RSP` の指す値をそのままリターンアドレスとして読み取る実装になっている。`break` は既定で関数プロローグ（`sub rsp, N` を含む）をスキップするため、ローカル変数を持つ関数では `sub rsp, N` 実行後の `RSP` を読むことになり、リターンアドレスではなく未使用のローカル変数領域（多くの場合 0）を読んでしまう。この場合 `up` は誤ったアドレス（例: `0x0`）に一時ブレークポイントを設定し、期待通りに動作しない。`testprog2.c` の `factorial`・`testprog3.c` の `worker` の双方で再現を確認済み。
- **リーク追跡の確保関数リターン待ちは 1 スロットのみ（v2.0 で判明）**: `malloc_ret_addr`（進行中の確保関数呼び出しのリターンアドレス追跡用一時ブレークポイント）は単一スロットである。エントリフック自体は他スレッドを一時停止して保護される（`suspend_other_threads`）が、リターン側のこの 1 スロットの制約自体は解消していないため、複数スレッドが同時に `malloc`/`calloc`/`realloc` の内部を実行中の場合はリターンアドレス追跡が競合しうる（5 章参照）。
- **メモリリーク検出の対応範囲が限定的**: `malloc`/`calloc`/`realloc`/`free` のみが対象で `new`/`delete` は追跡されない。また CRT が動的リンクされた対象（既定の `/MD`）ではシンボルが解決できず利用できない（4.2 節・5 章参照）。
- **リーク追跡と `next`/`step` の相互作用**: `leak on` 中に `n`（ステップオーバー）や `step` で `malloc`/`free` を呼ぶ行をまたぐと、内部的な計装処理（後述の詳細処理設計書 16 章参照）が 1 回分の内部シングルステップを消費するため、ごくまれに行の境界判定に影響する可能性がある（実害としては通常観測されないが、既知の相互作用として記録する）。
- **`show globals` は CRT 内部のグローバル変数も表示する**: `show globals` はモジュール内の全グローバルデータシンボルを列挙するため、CRT を静的リンクした対象（`/MT`/`/MTd`）では数百件の CRT 内部変数（`__acrt_...` 等）がユーザー定義のグローバル変数と混在して表示される。CRT を動的リンクした対象（既定の `/MD`）では CRT 内部変数が別モジュール（`ucrtbase.dll` 等）にあるため表示されず、より簡潔な一覧になる。
- **ブレークポイント・ウォッチポイントはプロセス間で自動伝播しない（v3.0 で判明・意図的な仕様）**: 親プロセスで設定したブレークポイント／ウォッチポイントは、後から生成された子プロセスには引き継がれない（各プロセスの `breakpoints`/`watchpoints` は完全に独立しているため）。子プロセス内の関数にも停止したい場合は、`process <id>` でその子プロセスへフォーカスを切り替えたうえで改めて `break`/`watch` を設定する必要がある。
